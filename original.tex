\subsection*{Question 2 (a)}
The methods Nesterov, Adam, and the constant baseline are compared across the three benchmarks in terms of how quickly they decrease the function value and how they behave during optimisation.
\paragraph{Convergence behaviour.}
Figure~\ref{fig:q2a_benchmarkA_objective} shows that, for Linear Regression, all three methods reduce the objective value and eventually reach almost the same minimum region. The steepness of the curve represents how quickly the function value decreases. Nesterov (blue) has the steepest initial decrease, so it reaches values close to zero first. However, it also shows a small bump around iteration 20, which suggests mild oscillation after the fast initial decrease. The gradient descent baseline (green) is the second fastest and gives a very smooth decrease. Adam (orange) is also smooth, but its curve is less steep than the other two, so it takes slightly longer to reach the same region. By around iteration 40, the three curves almost fully overlap, which means that all methods have reached a similar objective value. Overall, Nesterov is fastest on this benchmark, while Adam and the baseline are smoother. This behaviour is reasonable because quadratic cost functions like Linear Regression usually have nice convergence behaviour. There is no ``one size fits all'' step size: the convergence rate depends on the function being minimised and on the chosen update rule. In this case, Nesterov benefits from momentum and decreases the objective fastest at the start, but the small bump shows the usual trade-off that momentum can introduce some oscillation.

\subsection*{Question 2 (d)}
The effect of batch size in Mini-Batch Stochastic Gradient Descent is analysed on the Linear Regression benchmark by comparing batch sizes 5 and 40. Figure~\ref{fig:q2d_batchsize_loss} shows that both batch sizes reduce the loss very quickly in the early updates and then stabilise at similar final values. A log scale is used here because the loss drops sharply at the start and then stays close to a small value, so the smaller differences after convergence are easier to see. In the earlier Q1 and Q2(a)--(c) plots, I used normal-scale plots for consistency across the benchmark comparisons, since those plots were mainly comparing methods across different problems rather than focusing on small fluctuations after convergence. The steep initial drop indicates that both methods move rapidly toward the minimum region. After this phase, the curves flatten out, showing that the methods have converged. However, there is a clear difference in smoothness. The batch size 40 curve (orange) is very smooth throughout, while the batch size 5 curve (blue) shows small fluctuations around the converged value. This indicates that smaller batches give noisier approximate gradients, whereas larger batches provide more stable approximations of the true gradient. Overall, both batch sizes achieve similar convergence speed, but batch size 40 is more stable after convergence.

\subsection*{Question 2 (e)}
The effect of noise in Mini-Batch Stochastic Gradient Descent is analysed on the Linear Regression benchmark by comparing the original noise level and a higher noise setting. In the original setup, a small output noise level of 0.1 is used. This matches the typical setup from the lectures, where a small amount of noise is added to simulate realistic data while still allowing the model to recover the underlying relationship. Following the assignment instructions, the noise level is increased to 0.6, making the data significantly noisier. Figure~\ref{fig:q2e_noise_loss} shows that all methods reduce the loss very quickly in the early updates and then stabilise. There is a clear separation between the original noise and higher noise settings. Under the original noise (blue and orange), both batch sizes converge to a much lower loss. Under higher noise (green and red), the loss stabilises at a significantly higher value. This shows that increasing the noise level in the data limits how well the model can fit the data, so the optimisation converges to a worse final objective value. Within each noise level, the effect of batch size is similar to Q2(d). For the original noise, batch size 40 (orange) is smoother than batch size 5 (blue), which shows small fluctuations. For the higher noise case, batch size 40 (red) is also smoother than batch size 5 (green), similar to the orange curve, while batch size 5 (green) shows visible fluctuations, similar to the blue curve. Overall, the noise level has a much stronger effect on the final loss than the batch size. Batch size mainly affects smoothness of the updates, while the noise level determines how low the loss can go.
